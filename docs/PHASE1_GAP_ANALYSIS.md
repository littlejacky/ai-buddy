# Phase 1 Gap Analysis & Engineering Roadmap

**项目名称：** AI Buddy  
**分析日期：** 2026-11-08  

---

## 一、技术差距对比矩阵 (Capability Gap Matrix)

| 核心领域 | Phase 0 基线现状 (As-Is) | Phase 1 目标规范 (To-Be) | 关键差距分析 (The Gap) | 实施落地优先级 |
|---|---|---|---|:---:|
| **数据库与持久化** | 零持久化；所有会话仅存于浏览器内存和临时生命周期 | Azure SQL / SQLite 双适配；EF Core 映射完整实体体系 | 缺少数据库选型、迁移机制、并发控制与仓储服务 | **P0 (Gate 1)** |
| **家长身份与多租户** | 前端 1+1 算术弹窗；无后端会话；无 Guardian 实体 | `IGuardianIdentityProvider` 接口；安全哈希 PIN 校验；家庭隔离 | 必须防止 IDOR 漏洞，保证家长对儿童数据的排他性控制 | **P0 (Gate 1)** |
| **儿童档案与设备绑定** | 前端 `mode: 'adult' \| 'child'` 硬编码传参 | `Family` -> `ChildProfile` -> `DeviceBinding` 结构；最多 2 儿童限制 | 无法多孩子区分，换设备丢失全部状态，无设备解绑机制 | **P0 (Gate 1)** |
| **细粒度授权合规** | 单一粗粒度隐私免责协议 | 6 项独立授权项 (语音/记忆/简报/转写/安全/位置)，按需开关与撤回 | 无授权记录审计，无法满足儿童个人信息保护合规审查 | **P0 (Gate 1)** |
| **会话持久化与转写** | 客户端通话结束直接 teardown，文字字幕丢失 | 独立业务 SessionId；`/checkpoint` 与 `/finalize`；乱序事件整理 | 无法沉淀转写，网络中断时缺少状态恢复依据 | **P0 (Gate 2)** |
| **异步任务执行** | 无法执行任何离线计算 | 事务性 Outbox 表；`OutboxBackgroundService` 状态机；防重复消费 | 需要支持 Azure App Service 多实例安全争抢与重试 | **P0 (Gate 2)** |
| **跨设备长期记忆** | 每次开启通话均为全新白板 | L1事实 / L2近期摘要 / L3待续主题；300~600 Token 精炼注入 | 缺乏记忆提炼管道、版本冲突合并与跨设备会话互斥租约 | **P0 (Gate 3)** |
| **今日探索简报** | 无简报功能 | 自动提炼话题、好奇心闪光点与亲子互动建议；家长专属查询 | 需防范伪造心理测试、防止虚构儿童言行，建立证据关联 | **P1 (Gate 4)** |
| **环境上下文 (Context)** | 模型不知道今天是星期几、所处时区与城市 | `ContextSnapshot` (UTC+时区+本地时间+适度城市) 实时注入 | 无法准确回答日常相对日期，需要端到端时区感知体系 | **P1 (Gate 5)** |
| **受控工具调用** | WebRTC 纯语音交流，无外部工具 | `IBuddyTool` 注册中心、时区时间、天气、确定性计算与受控搜索 | 需隔离不可信网络数据，防范 Prompt Injection 攻击安全底线 | **P1 (Gate 5)** |
| **BuddyCanvas 动态UI** | 纯语音光球与线性文字流 | 知识卡、选择测验、翻转卡、分支故事；交互结果实时送回对话 | 需建立严格 JSON Schema 验证与双向 SSE/HTTP 事件总线 | **P1 (Gate 6)** |
| **儿童安全机制** | 仅依靠 System Instruction 约束 | S0/S1/S2 三级风险评定；SafetyEvent 独立加密与家长审计 | 需避免模型因误触敏感词挂断电话，保护儿童安全求助通道 | **P1 (Gate 7)** |
| **自动化测试** | 0 测试用例 | 后端 xUnit 集成测试 + 前端 Vitest 组件测试 + 核心场景 E2E | 缺乏对并发、幂等、授权边界和记忆注入的自动化回归保障 | **P0 (跨全阶段)** |

## 二、关键技术攻关与风险控制

1. **WebRTC 工具调用与信令协同**：
   - 当前客户端直连 Azure `/calls`，浏览器 DataChannel 为白名单过滤模式。
   - **应对策略**：构建 `ToolRegistry` 与受控信令中继通道；若底层 WebRTC DataChannel 无法双向透传自定义 Function Call，采用“后端受控调度 + 动态 SSE/EventStream 同步”方案，保证实时媒体流与 UI 交互完美协同。

2. **跨设备并发会话争抢 (Race Conditions)**：
   - 同一儿童若在手机和平板同时开麦，将造成记忆冲突与费用超标。
   - **应对策略**：在数据库引入 `ChildSessionLease`，心跳续约 + 悲观互斥锁定，后来者获得友好提示“Buddy 正在另一台设备上陪伴你哦”。

3. **合规审查与最小化暴露**：
   - 严禁向外部大模型或搜索引擎直接发送儿童真实姓名、年龄与原始语音。
   - 所有外部查询必须经过脱敏的“最小化意图抽取器”。
